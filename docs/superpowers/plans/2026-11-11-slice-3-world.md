# Slice 3: The World Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw the roster's agents as riders on one growing isometric pixel-art map, a plot per project, each rider at the building that matches the work it is doing.

**Architecture:** Three parts, each its own ticket, branch and pull request. **A** teaches the roster what kind of work a running agent is doing, read from its transcript. **B** is a Blender script that renders every sprite from simple 3D shapes, plus an import rule so Unity treats them as crisp pixel art. **C** is the world view: a pure model built from the roster snapshot, isometric layout maths, a Unity Tilemap for the ground, sprites for buildings and riders, pan and zoom.

**Tech Stack:** Unity 6000.4.3f1, C#, `UnityEngine.JsonUtility`, isometric `Tilemap` (built-in module), `SpriteRenderer`, IMGUI for text, Unity Test Framework (EditMode), Blender 5.1 in background mode with its bundled numpy. No new Unity package.

**Spec:** Tickets GRID-10 (part A), GRID-11 (part B), GRID-12 (part C), children of GRID-9; and slice 3 of the approved product requirements (kept privately; its rules are restated below). Data shape: `docs/roster-snapshot.md`. Patterns: `Assets/TheGrid/Core/Roster.cs`, `SessionFiles.cs`, `Collector.cs`, `Assets/TheGrid/RosterApp.cs`.

## Global Constraints

- Everything shown is true: a rider moves only because its agent's activity or state changed. The only other motion is the bounce of a rider that needs the owner.
- A guess is never shown with confidence. Activity that cannot be told is `working`.
- The world and the roster never disagree: both are drawn from the same `RosterSnapshot` object in the same frame.
- The only attention signal is a bouncing sprite. No sound, no notifications.
- 16-bit pixel art: point filtering, whole-number scaling, one fixed palette, no half-transparent pixels. All art is original and generated by this project's own script.
- Names and counts are text drawn at the screen's own sharpness.
- The roster and the review pile keep working; the 117 existing EditMode tests pass.
- 10 frames a second stays. Idle processor use stays near 6.5% of a core.
- Nothing leaves the machine. Agent app storage is read-only. The world's own file lives beside `settings.json`.
- Usable from 360 points wide.
- The repo is public. No real names of people, companies, accounts, repos or sessions in code, tests, fixtures or docs.
- Only one copy of the app runs at a time on the owner's Mac. Ask before launching a build while theirs is open.
- After opening each pull request, post `@codex review`; post it again after every push that answers findings.

## Decisions made in this plan

The reviewer's to veto:

1. **Activity comes from the last tool used, then from keywords.** `Edit` or `Write` is editing. `Read`, `Grep`, a web fetch is reading. A shell command that runs tests is testing. `git diff`, `git log`, `git commit`, `git push`, `gh pr`, or a review skill is reviewing. With no tool in the agent's last message, keywords in its text decide. Anything else is `working`.
2. **Ten buildings per plot.** Five for work: Garage (editing), Library (reading), Lab (testing), Review hall (reviewing), Workshop (working). Five for stopped riders: Booth (blocked on a question), Gate (waiting for permission or on something else), Yard (errored or unknown), Lot (done), Depot (offline).
3. **Activity can be up to 2 seconds old** and is refreshed without running `claude` more often: while any agent is running, the roster is rebuilt from the last session list on every poll, and only transcripts that changed are re-read.
4. **Art is rendered by a Blender script, not drawn at run time.** Boxes with flat colours, a fixed isometric camera, no smoothing, then every pixel snapped to the palette. The PNGs are committed, so building the app does not need Blender.
5. **Riders are rendered larger than true scale** so a bike and rider can be told apart, in four facings. Their glow line is white in the PNG and tinted per account when drawn.
6. **One map, a 12 by 12 tile plot per repo, laid out in a square spiral** from the centre. A repo keeps its plot for good; the list is saved in `world.json`. The map has no fixed size: it is as large as the plots in use.
7. **Unity's isometric Tilemap for the ground**, sprites for everything standing on it. One art pixel is one Unity unit.
8. **Pan by dragging or two-finger scroll; zoom in whole-number steps** with pinch, or `+` and `-`. Zoomed out far enough, building and rider names are hidden and each city shows its name and how many riders need the owner.
9. **No building interiors.** Clicking a rider shows that agent's roster row under the map.
10. **View switch.** Wide window: `Lists` and `World`. Narrow window: `Agents`, `Messages`, `World`.
11. **Picture mode for checking.** `-snapshot <file> -shots <folder>` draws the world from a snapshot file instead of live sessions, saves PNGs and quits. It reads no agent data.

Not in this plan: building interiors, animation beyond the bounce and straight-line rides, sound, other agent apps, art packs, moving or removing a plot, roads between cities.

## Review Focus

1. A transcript whose last assistant record is half-written, has no tool and no text, or is a subagent's: activity falls back to `working`; nothing throws. (A1)
2. A user message that merely contains the word "assistant" or "review": it is not mistaken for the agent's own words. (A1)
3. No agents, and 200 repos: the world says so in text; plots stay distinct; nothing throws. (C1, C2)
4. `world.json` missing or corrupt: plots start again from empty and the bad file is kept as `world.json.bad`. (C1)
5. Fifty riders at one building, and a repo that appears for the first time while the app is open: every rider has its own spot; the new plot is drawn without disturbing the others. (C2, C4)

Behaviour:
- `RosterApp` loads `Plots` from `world.json` beside `settings.json`, builds the `WorldModel` once per Layout pass from the snapshot it draws the roster from, and saves `Plots` when a plot was added.
- A `Grid` with isometric layout and a `Tilemap` hold the ground. When a city first appears, its 12 by 12 plot is painted (`tile-plot` with `tile-road` along the building fronts) and its ten building sprites are created. Existing plots are not touched.
- One sprite per rider at `Iso.RiderSpot`, tinted by account; `rider-small` sprites trail a rider with subagents; Depot riders are dimmed. Draw order is by screen height, so nearer things cover farther ones.
- First sight: placed directly. Building or slot changed: a straight ride over 1.2 seconds, facing the way it travels. Nothing else moves, except the two-position bounce (2 pixels, every 0.4 seconds) of a `marker` over each rider that needs the owner.

- Text: at zoom 3 and above, building names and rider names. Below that, each city's name and `n need you`, with a bouncing marker over a city that has any.
